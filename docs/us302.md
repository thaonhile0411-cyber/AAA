# US-302 — Scoring & Detailed Answers

US-302 grades the Supabase Reading/Listening bank on the server, stores one
idempotent result per submission, and returns explanations only after submit.

## Architecture

- `practice_answer_keys`: private accepted answers, display answer, explanation,
  passage evidence and audio segment. Browser roles have no `SELECT` grant.
- `practice_exercise_grading`: private Listening transcripts and optional,
  test-specific band scales.
- `practice_attempts`: immutable result snapshot. RLS permits only the owner to
  read it; writes go through the grading function.
- `practice_completion_events`: transactional outbox for US-401. Its primary key
  is the attempt ID, so retries cannot duplicate completion events.
- `grade_practice_attempt`: `SECURITY DEFINER` PostgreSQL function that uses
  `auth.uid()`, normalizes case/whitespace, calculates totals, and atomically
  saves the attempt/event.
- `POST /api/practice/[slug]/submit`: authenticated server endpoint. It validates
  IDs and bounded strings, invokes the function and exposes `Server-Timing`.
- `GET /api/practice/results/[attemptId]`: owner-only result lookup through RLS.

Migrations `0009_us302_scoring_schema.sql` and `0010_us302_answer_keys.sql`
contain the schema and all 40 keys for the current eight US-301 exercises.

## Result behavior

- Summary: correct, incorrect, unanswered, percentage and raw score.
- Incorrect and unanswered questions are red and show the correct answer.
- Every question exposes an explanation button.
- Reading scrolls to and highlights the source paragraph.
- Reading also highlights the exact evidence phrase inside that paragraph while
  preserving the learner's own highlight/note ranges.
- Listening reveals the complete transcript, highlights the evidence phrase and
  provides a replay/pause button for that answer segment.
- The current exercises contain only five questions. There is no approved IELTS
  conversion for these short tests, so `estimatedBand` is deliberately `null`.
  Add a reviewed test-specific `band_scale` before showing a band; never invent
  one from percentage alone.
- Migration `0011_us302_harden_grading.sql` rejects an incomplete review setup:
  Reading requires an evidence paragraph for every question; Listening requires
  a full transcript and start/end audio positions for every question. An
  optional `band_scale` must be a documented raw-score map such as
  `{ "0": 3, "1": 3.5 }`; missing scores fail closed rather than producing a
  made-up band.
- US-103 keeps its own validated totals (Listening 10, Reading 12); US-302 does
  not change placement scoring.

## Idempotency and security

The browser creates a UUID `submissionId`. The unique constraint on
`(user_id, submission_id)` makes a network retry return the original snapshot.
The API never accepts a user ID from the browser. Answer keys and transcripts
are unavailable through public table queries.

## Verification

```powershell
npm.cmd test

npm.cmd run lint
npm.cmd run build
npm.cmd run test:integration   # requires local Supabase/Docker
```

The integration runner verifies real cookies, private keys, owner-only results,
case-insensitive gap-fill, unanswered questions, transcript segments, retry
idempotency and a local server grading response below 500 ms.
