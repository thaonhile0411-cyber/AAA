# US-402.2 — Adaptive Roadmap Adjustment

`POST /api/v1/roadmap/recalculate` recalculates the active learner-owned roadmap after a completed `reassessment` (the US-402.1 Progress Test contract in this codebase).

## Decision rules

Each of the four skills must have comparable, complete baseline and reassessment bands. The phase target is the smaller of the learner's goal band and baseline + 0.5.

| Result | Rule | Next-phase action |
| --- | --- | --- |
| Qualifying gain | Gain >= 0.5 and new band reaches the phase target | One higher-range task; difficulty starts at new band + 0.5. |
| No change | Absolute change < 0.01 | Two ten-minute foundational review tasks at the start of the next phase/week. |
| Decline | Change < 0 | Two ten-minute targeted review tasks and a lighter-pace recommendation. |
| Other improvement | Gain is positive but does not meet the qualifying rule | One continuation task; difficulty is unchanged from the normal next range. |
| Missing/incomparable result | Any skill is unavailable | Return 422; no roadmap mutation. |

The maximum generated adjustment is eight ten-minute review tasks (80 minutes). The persisted plan records its total alongside the learner's daily availability × seven. The UI discloses a schedule risk if a future rule ever exceeds that budget.

## Safety and idempotency

- The endpoint authenticates the caller and queries only their active roadmap and assessments.
- The RPC verifies that both assessment IDs belong to `auth.uid()`.
- `roadmap_adjustments` has a unique `(roadmap_id, source_assessment_id)` constraint. Repeating a request returns the original adjustment instead of duplicating tasks or versions.
- `apply_roadmap_recalculation` locks the roadmap row and performs audit insert, unfinished-task annotations, phase creation, and roadmap version update in one database transaction.
- Its `UPDATE roadmap_activities` statement always includes `completed_at is null`; completed activity history is never modified.

## Performance check

The API returns `durationMs` for the request path. Under the documented normal condition (one active roadmap, four skill rows, and no more than eight generated tasks), the target is under 1,000 ms. `tests/adaptive-roadmap.test.ts` covers the deterministic calculation; integration performance should be measured against the deployed Supabase instance because database network latency is environment-specific.
